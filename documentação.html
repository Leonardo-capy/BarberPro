BarberPro

Sistema web completo de agendamento online para barbearias, desenvolvido com React no frontend e Node.js/Express no backend, com banco de dados SQLite e autenticação por sessão.

React 18 FullCalendar Context API Node.js Express Bcrypt SQLite express-session
01

Visão Geral do Projeto

📋

O BarberPro é um sistema full stack voltado para barbearias que precisam gerenciar agendamentos online. O sistema oferece três níveis de acesso distintos — cliente (público), barbeiro e administrador total — com interfaces e permissões específicas para cada perfil.

Objetivo educacional: Projeto desenvolvido para prática real de desenvolvimento full stack, simulando um sistema profissional com separação de responsabilidades, autenticação completa, controle de acesso baseado em roles e regras de negócio complexas.

Banco de Dados

🗄️

Banco relacional SQLite com 4 tabelas principais, inicializado automaticamente na primeira execução.

usuariosArmazena barbeiros e administradores
idINTEGER PKIdentificador único autoincrement
usuarioTEXT UNIQUENome de login único
senhaTEXTHash bcrypt da senha
planoTEXT'ativo' para aparecer como barbeiro disponível
roleTEXT'admin' ou 'barbeiro'
descricaoTEXTTexto de perfil do barbeiro
created_atDATETIMEData de criação (automática)
agendamentosRegistros de agendamentos dos clientes
idINTEGER PKIdentificador único
user_idINTEGER FKBarbeiro responsável (ref. usuarios)
nomeTEXTNome do cliente
telefoneTEXTDDD + número (somente dígitos)
servicoTEXTNome do serviço no momento do agendamento
precoREALValor cobrado pelo serviço
dataTEXTData no formato YYYY-MM-DD
horarioTEXTHorário no formato HH:MM
finalizadoINTEGER0 = pendente · 1 = finalizado/pago
bloqueiosHorários e dias bloqueados por barbeiro
user_idINTEGER FKBarbeiro dono do bloqueio
dataTEXTData do bloqueio (YYYY-MM-DD)
horarioTEXT'HH:MM' para hora específica · 'DIA_INTEIRO' para bloquear o dia
servicosCatálogo de serviços por barbeiro
user_idINTEGER FKBarbeiro dono do serviço
nomeTEXTNome do serviço (ex: "Corte + Barba")
precoREALPreço em reais

Horários disponíveis são fixos no backend: 09:00 · 10:00 · 11:00 · 13:00 · 14:00 · 15:00 · 16:00 · 17:00

Segurança

🔐
  • 🔑
    Bcrypt para senhas — Todas as senhas são armazenadas como hash bcrypt com salt de fator 10. Comparações usam bcrypt.compare() para prevenir timing attacks.
  • 🍪
    Express-session com cookie seguro — Cookies configurados com httpOnly: true e secure: true em produção. sameSite: 'none' no ambiente de produção para compatibilidade com proxy reverso.
  • 🛡
    Helmet.js — Headers HTTP de segurança configurados, incluindo Content Security Policy, desativação do header x-powered-by e política CORS configurada por origin.
  • 🎭
    Middleware de roles — Funções verificarLogin, verificarBarbeiroOuAdmin e verificarAdminTotal protegem as rotas conforme o nível de acesso necessário.
  • ✔
    Validação de inputs — Campos de texto são validados quanto ao tipo, comprimento mínimo e valores permitidos antes de qualquer operação no banco de dados.
  • 🔒
    SESSION_SECRET obrigatório em produção — O servidor aborta a inicialização se a variável de ambiente SESSION_SECRET não estiver definida em ambiente de produção.

Regras de Negócio

📏
✗Não permite agendamento em datas passadas
✗Não permite agendamento aos domingos
✗Não permite dois agendamentos no mesmo horário e barbeiro
✗Não permite agendamento em horário ou dia bloqueado
✓Cada barbeiro vê e gerencia apenas seus próprios dados
✓Horários fixos definidos no backend — não editáveis via frontend
✓Preço e nome do serviço são gravados no agendamento no momento da criação
✓Bloqueio de dia inteiro usa o valor especial DIA_INTEIRO
✓Telefone é sanitizado — apenas dígitos numéricos são aceitos (10–11 dígitos)
✓Admin principal (ID 1) não pode ter sua role alterada

Como Executar

🚀

1. Backend

# Na pasta /backend
npm install
node server.js

# Servidor disponível em:
http://localhost:3000

2. Frontend

# Em outro terminal, na pasta /frontend
npm install
npm start

# Interface disponível em:
http://localhost:3001
Produção: O backend serve os arquivos estáticos do frontend/build quando NODE_ENV=production. Defina SESSION_SECRET como variável de ambiente obrigatória antes de subir para produção.
